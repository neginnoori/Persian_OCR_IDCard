# API ویندوز کارت ملی با FastAPI و Swagger

این پروژه همان مسیر اصلاح‌شدهٔ OCR را به سرویس HTTP تبدیل می‌کند:

عکس → DINO/SAM → صاف‌کردن کارت و تعیین جهت → Paddle Detection → Hezar CRNN → شش فیلد JSON.

پیش‌فرض `rectify_best_effort` است. هشدار هندسه یا جهت در خروجی می‌ماند و OCR روی تصویر موجود اجرا می‌شود. مقدار ناموجود `null` است؛ کد ملی و تاریخ رشته هستند و صفر ابتدایی حفظ می‌شود. این سرویس استخراج اطلاعات است و اصالت کارت یا هویت مشتری را تأیید نمی‌کند.

## پیش‌نیازهای سیستم شرکت

- Windows x64 و Python **3.11 x64** همراه Python Launcher (`py`).
- GPU انویدیا و درایوری که اجرای PyTorch با CUDA 12.6 را پشتیبانی کند. نصب‌کننده با محاسبهٔ واقعی روی GPU آن را بررسی می‌کند.
- اینترنت برای نصب وابستگی‌ها و اولین دانلود وزن‌ها؛ وزن‌ها پس از دانلود کش می‌شوند.
- فایل کامل مخزن، شامل `packages/cardid-extractor` و `projects/dino-sam-hezar-colab`. تنها پوشهٔ API را کپی نکنید.

این نسخه Torch/Hezar و مدل‌های آماده‌سازی را روی GPU و Paddle Detection را در پردازش مجزای **CPU** اجرا می‌کند. دو محیط Python، تداخل OpenCV و کتابخانه‌های Torch/Paddle را کاهش می‌دهند. هنوز مصرف VRAM/RAM و اجرای واقعی مدل‌ها روی ویندوز شرکت اندازه‌گیری نشده است؛ اجرای موفق تست‌های API به معنی تأیید سخت‌افزار یا دقت OCR نیست.

## نصب

مخزن/ZIP برنچ API را دریافت و استخراج کنید. سپس در PowerShell:

```powershell
cd C:\Projects\Persian_OCR_IDCard\projects\windows-fastapi
py -3.11 --version
nvidia-smi
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
```

`ExecutionPolicy Bypass` فقط برای همان پردازش PowerShell است و تنظیم سراسری سیستم را تغییر نمی‌دهد.

نصب‌کننده این موارد را ایجاد می‌کند:

| مسیر | کاربرد |
|---|---|
| `.venv` | FastAPI، Torch، Hezar و بسته‌های محلی OCR |
| `.venv-paddle` | Paddle Detection و وابستگی‌های مستقل آن |
| `.venv/paddle-worker.json` | مسیر Python پردازشگر Paddle |
| `.env` | تنظیمات خصوصی و API Key تصادفی |
| `models` | کش وزن‌ها پس از شروع مدل‌ها |

کلید API در خروجی نصب چاپ نمی‌شود. `.env` را با ویرایشگر محلی باز کنید و مقدار `OCR_API_KEY` را برای تست Swagger بردارید. فایل را وارد Git یا فایل ZIP قابل اشتراک نکنید. نصب مجدد کلید موجود را عوض نمی‌کند.

وابستگی‌ها در `requirements.txt` و `requirements-api.txt` برای محیط اصلی و `requirements-paddle.txt` برای محیط مجزای Paddle ثبت شده‌اند. نصب پیشنهادی از طریق اسکریپت است؛ دستور سادهٔ `pip install -r requirements.txt` به‌تنهایی CUDA، بسته‌های محلی و محیط Paddle را آماده نمی‌کند. این فایل‌ها نسخهٔ وابستگی‌های مستقیم را تثبیت می‌کنند و lockfile کامل وابستگی‌های غیرمستقیم نیستند.

## اجرا و Swagger

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1
```

مدل‌ها یک بار هنگام شروع سرویس بارگذاری می‌شوند. اولین اجرا برای دانلود وزن‌ها زمان می‌برد. بعد از آماده‌شدن:

- Swagger: <http://127.0.0.1:8000/docs>
- OpenAPI: <http://127.0.0.1:8000/openapi.json>
- سلامت سرویس: <http://127.0.0.1:8000/health/live>
- آمادگی مدل‌ها: <http://127.0.0.1:8000/health/ready>

در Swagger روی **Authorize** کلیک کنید و فقط مقدار API Key را وارد کنید؛ پیشوند `Bearer` لازم نیست. سپس `POST /v1/ocr` → **Try it out** → انتخاب فایل JPEG/PNG → **Execute**. نام فیلد فایل `file` است. هدر احراز دسترسی `X-API-Key` است.

برای پورت دیگر:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 -Port 8001
```

با `Ctrl+C` سرویس را متوقف کنید. خروجی گزارش شامل request ID، وضعیت پردازش، متن خام، متن نرمال‌شده، شش فیلد، کادرها، هشدارها و زمان پردازش است. مختصات کادرها در `coordinate_space` اعلام می‌شود؛ در مسیر معمول نسبت به کارت صاف‌شده‌اند، نه عکس اولیه. `processed_image_size` ابعاد همان تصویر است.

## تنظیمات `.env`

| متغیر | پیش‌فرض | معنی |
|---|---|---|
| `OCR_API_KEY` | کلید تولیدشده در نصب | حداقل ۳۲ کاراکتر ASCII؛ برای درخواست OCR لازم است |
| `OCR_MODEL_DIR` | `./models` | محل کش وزن‌ها، نسبت به پوشهٔ API |
| `OCR_MAX_UPLOAD_MB` | `15` | حداکثر اندازهٔ فایل بر حسب MiB |
| `OCR_MAX_PIXELS` | `25000000` | حداکثر تعداد پیکسل تصویر |
| `OCR_MAX_PENDING` | `2` | درخواست‌های منتظر، علاوه بر یک کار فعال |
| `OCR_REQUEST_TIMEOUT_SECONDS` | `180` | حداکثر انتظار پاسخ پردازش |
| `OCR_UPLOAD_TIMEOUT_SECONDS` | `30` | حداکثر زمان دریافت بدنهٔ درخواست |

سرویس یک worker پردازش دارد و کارها را سری روی GPU اجرا می‌کند. از `--reload` یا چند Uvicorn worker استفاده نکنید؛ هر worker مدل‌ها را دوباره در حافظه بارگذاری می‌کند. پرشدن صف پاسخ `503` می‌دهد. timeout پاسخ به معنی قطع فوری محاسبهٔ در حال اجرای GPU نیست: کار فعال ممکن است ادامه پیدا کند و ظرفیت آن تا پایان آزاد نمی‌شود.

## قرارداد خطاها

| HTTP | معنی |
|---|---|
| `400` | فایل خالی یا تصویر خراب |
| `401` | API Key ناموجود یا نادرست |
| `408` | زمان دریافت فایل تمام شده است |
| `413` | حجم یا تعداد پیکسل بیش از حد مجاز |
| `415` | فرمت پشتیبانی‌نشده یا تصویر چندفریمی |
| `422` | درخواست مطابق schema نیست، مثلاً فیلد فایل وجود ندارد |
| `503` | سرویس آماده نیست یا صف پر است |
| `504` | زمان انتظار پردازش تمام شده است |
| `500` | خطای داخلی پردازش؛ request ID برای پیگیری برگردانده می‌شود |

پاسخ موفق می‌تواند `ocr_candidate` یا `no_text` باشد. `candidate` یا معتبر بودن قالب، تضمین درست بودن مقدار نیست. وضعیت و `review_required` هر فیلد را در برنامهٔ مصرف‌کننده بررسی کنید.

## نگهداری و دسترسی شبکه

اسکریپت اجرا فقط به `127.0.0.1` گوش می‌دهد؛ برای تست روی همان سیستم است. برای دسترسی شبکهٔ شرکت، مدیر سیستم باید reverse proxy با HTTPS، کنترل دسترسی و محدودیت درخواست تنظیم کند. سرویس را مستقیماً روی اینترنت منتشر نکنید.

API تصاویر و نتایج کارت را در پروژه ذخیره نمی‌کند و لاگ دسترسی Uvicorn در اسکریپت غیرفعال است. فایل موقتی آپلود در چرخهٔ درخواست بسته می‌شود. لاگ سفارشی نباید متن OCR، عکس یا API Key را ثبت کند. کش وزن‌ها دادهٔ کارت نیست.

بعد از دریافت نسخهٔ تازهٔ کد، دوباره `setup.ps1` را اجرا کنید. اسکریپت اجرا هش سورس OCR را با نسخهٔ نصب‌شده مقایسه می‌کند و از اجرای کد قدیمی جلوگیری می‌کند. محیط‌های `.venv` را بین مک و ویندوز یا بین ماشین‌های مختلف کپی نکنید؛ روی مقصد از سورس نصب کنید.

## تست بدون دانلود وزن‌ها

تست‌های API مدل‌ها را با backend آزمایشی جایگزین می‌کنند؛ برای بررسی endpoint، احراز دسترسی، فایل ورودی، صف و پاسخ هستند. برای اجرا در محیط توسعه:

```powershell
py -3.11 -m venv .venv-api-tests
.\.venv-api-tests\Scripts\python.exe -m pip install -r requirements-test.txt
.\.venv-api-tests\Scripts\python.exe -m pytest tests -q
```

این محیط آزمایشی مستقل از نصب GPU است و فقط قرارداد API و مدل‌های آزمایشی را اجرا می‌کند؛ برای سرویس واقعی همان `.venv` ساخته‌شده با `setup.ps1` لازم است.

تست نهایی ویندوز باید با GPU واقعی، چند تصویر مستقل، چهار جهت اصلی، کارت کج و تصویر ازقبل‌برش‌خورده انجام شود. نمونه‌های واقعی کارت را به مخزن Git اضافه نکنید.
